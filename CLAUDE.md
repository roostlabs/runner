# runner

Процес на VPS дева. Go, модуль `github.com/roostlabs/runner`.

Ширший контекст — `../.github-private/PROJECT_CONTEXT.md` (архітектурні рішення)
і `../.github-private/roadmap.md` (фази). Контракт каналу — `../protocol/PROTOCOL.md`.
Прочитай перед змінами.

## Правила цього репо

- **Креди не йдуть угору.** Ніколи. У Cloud — лише булеві прапорці (`cred.status`).
  Значення живуть у конфізі (`0600`) і потрапляють у sandbox як env на час задачі.
  `cmd_output` перед відправкою чиститься через `config.Creds.Values()`.
- **Спочатку журнал, потім стрім.** Подія пишеться в event-store і лише потім
  йде в канал. Інакше обрив каналу = втрачена історія.
- **Агент виконує код лише в контейнері.** Ніколи на хості. Ліміти `--cpus`/
  `--memory` обов'язкові.
- **Агент діє тільки через `agent.Session`.** Інтерфейс реалізує executor —
  саме тому контейнер, редакція, журнал і бюджет тримаються незалежно від того,
  що вирішить модель. Не давай агенту прямий доступ до sandbox, repo чи store.
- **Креди не йдуть і до провайдера моделі.** Усе, що агент читає — вивід команд,
  вміст файлів — проходить через той самий фільтр, що й `cmd_output`.
- **Бюджет зупиняє задачу, а не просто рахує.** Перевірка перед викликом, по
  вже витраченому: перевитрата максимум на один виклик.
- **Concurrency = 1** за замовчуванням. Цільова тачка — 1 CPU / 2GB.
- **Обрив каналу — норма, не помилка.** Задача продовжує працювати. Реконект з
  backoff + jitter. Не роби graceful-close на мертвому з'єднанні: бібліотека
  чекає close-frame 5 секунд — використовуй `CloseNow()`.
- **Невідомий `type` ігнорується мовчки**, ніколи не reject.
- Залежності — тільки cgo-free (бінарник має лишатись статичним для інсталера).
  Зараз їх дві: `coder/websocket`, `modernc.org/sqlite`. Нову додавай лише за
  вагомої причини. Клієнта Anthropic серед них немає навмисно: `internal/llm`
  ходить у HTTP напряму, бо потрібен вузький зріз API (один ендпойнт, tool use,
  лічильники токенів), і цей зріз менший за саму залежність.
- Публічний репо — коментарі й документація англійською.
- Не пиши заглушку, що вдає роботу. Нереалізоване — відповідай чесною помилкою
  (див. `handleTaskRun`).

## Режими кредів (Local / Managed)

`creds.mode` у конфізі: `local` (дефолт, і порожнє значення = local) або
`managed`. Local — значення задає дев на VPS, `cred.set` із каналу
**відмовляється**. Managed — Cloud може писати значення вниз каналом.

- **Managed вмикається тільки в конфізі на VPS.** Не через дашборд, не через
  канал. Уся суть режиму — згода дева на транзит секрету через Cloud; якби Cloud
  сам собі цей дозвіл видавав, це не був би дозвіл. Зміна режиму = рестарт.
- **Невідомий `mode` — помилка валідації**, не «схоже на managed». Опечатка не
  має fail-open у бік, де Cloud уміє писати.
- `cred.set` у Local-режимі **навіть не декодується**: значення, якого не
  просили, не варто виймати з кадру.
- **Порядок у `setCred` не випадковий**: перевірка режиму → перевірка, що задача
  не біжить → `buildCreds` (чи Runner узагалі зможе цим користуватись) → запис
  на диск → застосування. Диск чіпається останнім, тож відмова не лишає в
  конфізі кред, яким жодна задача не скористається.
- **Задача, що вже біжить, блокує зміну.** Інакше вона запушила б під одним
  токеном, а PR відкрила під іншим.
- Креди задачі резолвляться на її старті (`executor.Creds` + `Config.Creds`),
  не при побудові екзекутора. Задача доживає зі своїм набором.
- Порожнє значення = стерти слот. Відкликаний токен має бути прибираним без ssh.
- У лог іде **ключ і булеве `set`**, ніколи значення. Підтвердження для Cloud —
  свіжий `cred.status`, тобто прапорці.

## Forge (`internal/forge`)

GitHub і GitLab. Провайдер вибирається за хостом ремоута; `github.com` і
`gitlab.com` відомі за іменем, усе інше — через `git.forge` у конфізі.

- **Не вгадуй self-hosted forge за хостнеймом.** Помилка тут = гілка запушена,
  PR не відкритий. Відмова до пушу — краща поведінка.
- Шлях репозиторію тримається **цілим** (`Remote.Path`), не розбитим на
  owner/name: у GitLab бувають підгрупи, і `group/sub/app` не зводиться до
  останніх двох сегментів. GitHub, навпаки, відмовляє на шляху з підгрупою.
- GitLab адресує проєкт URL-енкодженим повним шляхом (`group%2Fsub%2Fapp`).
  У тестах перевіряй `r.URL.EscapedPath()`, а не `r.URL.Path` — останній уже
  декодований, тож слеші «зникають».
- Токен: GitHub — `Authorization: Bearer`, GitLab — `PRIVATE-TOKEN`. Не слати
  обидва.
- В помилку йде **шлях**, не повний URL: у `apiBase` можуть бути креди в
  userinfo, а помилка потрапляє в журнал і в канал.
- `remove_source_branch: false` для GitLab — гілка це результат задачі.

## Tracker (`internal/tracker`)

Jira і Linear за одним інтерфейсом (`Get`, `List`, `Transition`, `Comment`).
Кред — `creds.taskManager`, решта — секція `tracker` у конфізі. Живе в Runner,
а не в Cloud, з тієї ж причини, що й forge: токен трекера — на VPS.

- **Провайдер тікета вирішує, чий він.** Executor чіпає тікет лише коли
  `ticket.provider == tracker.kind`. `manual` із дашборду — нічий, навіть якщо
  id схожий на ключ Jira.
- **Тікет — до репи.** `pickUp` (читання тексту + перехід у `inProgress`) іде
  перед `prepare-repo`. Трекер, що недоступний зараз, не прийме PR і пізніше;
  дізнатись про це до витрат агента дешевше, ніж після.
- **Текст тікета дочитується лише коли порожній.** Cloud шле `title`/`body`,
  коли має (рішення 12 не скасоване); Runner добирає їх сам, коли їх немає —
  так виглядає тікет із поллінгу.
- **`handOver` — частина задачі, не бонус.** Провал коментаря/переходу після
  PR = задача `failed`, але `task.result.prUrl` лишається. Другої нотатки про
  провал тоді не буває (перевірка `prURL == ""`).
- **Нотатки на тікет проходять redaction** (`session.scrub`) — коментар у
  трекері «зовні» так само, як рядок у каналі.
- **Поллінг вимагає `states.inProgress`.** Інакше готовий тікет лишається
  готовим і запускався б щохвилини. Це перевірка конфігу, не рантайму.
- Поллер бере **один тікет за раунд** (concurrency = 1) і не питає трекер,
  поки задача біжить. Тікет, що лишився в ready після старту, повторюється
  через `retryAfter` (10 хв), не щораунд.
- Jira: `Authorization: Basic email:token`; описи — ADF, зводяться в текст
  (`adfText`), коментарі будуються назад (`adfDocument`). Пошук — через
  `POST /rest/api/3/search/jql` (старий `/search` знято). Переходи
  резолвляться щоразу — вони per-issue.
- Linear: GraphQL, `Authorization: <api key>` без Bearer. `issue(id:)`
  приймає `ENG-12`; мутації хочуть uuid, тому перед ними — lookup. Стани
  шукаються в команді тікета (`team.key`), не в `tracker.project`.

## Інсталер (`install.sh`)

POSIX sh, без залежностей крім curl/wget. Цілі — Linux + systemd; macOS/Windows —
відкрите питання, не вирішуй сам.

- **Ніколи не перезаписує конфіг** без `--force-config`. Там усі креди машини;
  one-liner, вставлений двічі, не має їх стерти.
- Відмовляє на `ws://` до віддаленого хоста (токен пішов би відкритим текстом) і
  на відсутній Docker (виконання лише в контейнері, фолбеку немає).
- Конфіг пишеться під `umask 077`, потім явний `chmod 0600` + `chown`. Режим
  `install(1)` застосовується **після** того, як контент уже на диску.
- Токен в argv видно в `ps` — тому є `--token-file` і `ROOST_TOKEN`.
- **EXIT-трап мусить повертати 0.** Під `set -e` провал останньої команди в трапі
  стає кодом виходу скрипта — інсталер рапортував би провал на успіху (це вже
  ловилось тестом, див. `packaging`).
- Перед комітом: `make lint-install` (shellcheck у контейнері) і
  `go test ./packaging/`.

## Перевірка перед комітом

```bash
gofmt -l . && go vet ./... && go test -race ./...
make lint-install
```

## Залежність від protocol

`go.mod` вимагає тег (зараз `v0.5.0`) і має
`replace github.com/roostlabs/protocol => ../protocol` для швидкої ітерації.

`replace` прибрати **не можна, поки `roostlabs/protocol` приватний**: модуль не
проходить через `proxy.golang.org`, тож `go build` без `replace` падає на
`git ls-remote ... exit status 128`. Тег є і відповідає коду — але зовні
недоступний. Коли репо стане публічним: `go mod tidy` (у `go.sum` немає запису
для protocol, бо `replace` його не потребує), потім прибрати `replace`.
